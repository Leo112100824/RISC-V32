# RISC-V 工程代码功能与设计说明

> 按仓库现有源码整理，更新日期：2026-10-26。本文面向理解工程和继续修改代码，不替代 RISC-V ISA 手册或仿真结果。本文覆盖 Git 仓库内的 RTL、测试、生成器与构建脚本，并说明工作区根目录的 Makefile 包装入口。除标注为“工作区根”的文件外，文中路径均相对于 Git 仓库根目录。当前活动 RTL 以 `model_tb/filelist.f` 为准；`rtl/legacy/` 是归档版本，不参与当前构建。

## 1. 工程在做什么

本仓库实现一个 32 位 RV32I 处理器，并扩展 Zicsr 机器模式 CSR 指令、MRET 和同步异常。当前主实现把取指拆成 IF1、IF2 两级，其余为 ID、EX、MEM、WB，因此整体是六级流水线：

```text
PC/指令地址 → 同步取指缓冲 → 译码/读寄存器 → 运算/分支 → 访存/CSR/异常 → 寄存器写回
     IF1              IF2                 ID             EX             MEM          WB
```

处理器通过外部接口接入指令存储器和数据存储器。指令侧按同步读存储器设计：本拍输出地址，下一拍得到指令；数据侧目前按组合读、同步字节写设计，没有 `ready` 或等待周期接口。活动实现支持 41 条 RV32I 基础整数指令、6 条 Zicsr 指令和 MRET；FENCE 在当前无 Cache 的模型中不改变数据，FENCE.I 会冲刷流水线。CSR/同步异常的行为和当前功能边界见后文。

## 2. 活动 RTL：当前处理器实现

下表中所有路径均相对于 `RISC-V32/`。这 17 个 Verilog 模块及其包含文件构成当前仿真/构建入口。设计分层的目的，是让时序边界、组合功能和控制策略分开验证，同时让顶层集中处理跨级控制与优先级。

| 文件 / 模块 | 功能与输入输出职责 | 为什么这样设计 |
|---|---|---|
| `rtl/riscv_def.vh`（宏定义） | 定义 XLEN、寄存器/CSR 宽度、指令格式与 opcode、内部指令编号、ALU/访存/分支/写回控制码、CSR 地址和异常原因。 | 把编码约定集中管理，避免各模块重复写魔数；活动 RTL 共用它，旧版另有自己的快照。修改控制编码时应同步检查所有使用端。 |
| `rtl/core/top.v`（`top`） | 处理器薄顶层，只把时钟、复位、指令/数据存储器接口和 trap 可观测信号连接到 `rv32_core`。 | 将处理器内部流水线与板级/仿真接口隔开；存储器可由不同的外部模型提供，核心无需内置特定 RAM。 |
| `rtl/core/rv32_core.v`（`rv32_core`） | 核心集成层。实例化六级流水线、冒险/前递、CSR 文件；连接各级流水寄存器，形成重定向、暂停、写回和 trap 通路；选择 MEM 与 EX 同拍异常中的较老事件，并将 trap 目标送回 IF1。 | 将全局连线和跨级优先级放在一个位置，使每个 stage 仍能独立测试。`top` 因此保持简单；`rv32_core` 也提供可测试的 trap 调试端口。 |
| `rtl/core/if_stage/if1_stage.v`（`if1_stage`） | 保存 PC，产生 `imem_addr`，按顺序加 4，接受 redirect；输出与同步读指令对齐的 PC 和有效标志。优先级为 redirect、stall、顺序取指。 | 同步 BRAM 的地址与数据相隔一拍，IF1 专门负责发地址；有效移位标记阻止复位后的未定义数据进入流水线。 |
| `rtl/core/if_stage/if2_stage.v`（`if2_stage`） | 捕获 `imem_rdata` 和对应 PC，形成送给 ID 的 head 项，并以 tail 项保存暂停期间到达的在途指令；按有效位和 PC 去重；flush 时清空。 | 停顿 IF1/IF2 时 BRAM 仍可能返回在途数据。单纯冻结会丢指令，直接重复接收又可能执行两次；一个 skid 项加 PC 去重可同时处理这两类情况。 |
| `rtl/core/id_stage/decoder.v`（`decoder`） | 组合译码指令，识别 RV32I、Zicsr、MRET、FENCE/FENCE.I，输出寄存器字段、实际使用的源寄存器、立即数、ALU/访存/分支/写回控制和系统指令标志；非法编码设 `illegal`。 | 合并旧版的指令识别与控制生成，减少模块间重复译码；默认输出先清零以避免 latch，非法指令不发出副作用控制。`rs1_used/rs2_used` 让冒险单元只检查真正被读的源。 |
| `rtl/core/id_stage/imm_gen.v`（`imm_gen`） | 从指令位域组合生成 I、S、B、U、J、CSR zimm 立即数，并按格式进行符号扩展或零扩展。 | 各指令格式的位排列不同；独立模块令编码拼接可单测，也避免 decoder 和执行级分别维护多份立即数逻辑。 |
| `rtl/core/id_stage/regfile.v`（`regfile`） | 32×32 位整数寄存器堆，两个组合读端口、一个时钟写端口；x0 恒为零，支持同拍写回到读地址时的写优先旁路。 | 两读一写匹配整数指令的常见数据通路；x0 语义由硬件保证；同拍旁路避免 WB 与 ID 读在边沿附近出现旧值。寄存器堆不依赖清零复位，软件/测试需先初始化将要读取的寄存器。 |
| `rtl/core/id_stage/id_stage.v`（`id_stage`） | 组合连接 decoder 与寄存器堆，向 hazard 暴露源寄存器信息，并把 PC、指令、操作数、立即数和控制信号锁存到 ID/EX；负责 flush 和 stall 时插入无效 bubble。 | 将 ID 的组合工作和流水线时序边界放在同一模块，接口清晰；stall 时保留前级并向下游注入 bubble，避免相关指令被重复推进。 |
| `rtl/core/hazard_unit.v`（`hazard_unit`） | 检查 EX 中有效 load 或 CSR 读的 `rd` 是否与 ID 中有效指令实际使用的 `rs1/rs2` 相同；非 x0 时产生一拍 stall。 | load/CSR 结果尚未能从 EX/MEM 前递，必须等到 MEM/WB；把冒险比较独立出来便于验证。无效/非法指令、x0 和未使用的源不会误触发暂停。 |
| `rtl/core/ex_stage/forward_unit.v`（`forward_unit`） | 为 EX 的两个源操作数选择寄存器堆值、EX/MEM 写回候选或 MEM/WB 写回值；较新的 EX/MEM 优先。排除 x0、load 和 CSR 的 EX/MEM 前递。 | 前递减少普通 RAW 依赖的停顿；优先使用最近生产者保证依赖链取最新结果。load 的 EX/MEM 值是地址而非数据，CSR 读取也尚未完成，所以交由 hazard stall 等待 MEM/WB。 |
| `rtl/core/ex_stage/alu.v`（`alu`） | 组合执行 ADD、SUB、SLL、SLT、SLTU、XOR、SRL、SRA、OR、AND；移位量取低 5 位。 | 把算术/逻辑运算收敛到一个小型组合单元；有符号与无符号比较明确区分，算术右移采用 signed 运算。 |
| `rtl/core/ex_stage/branch_unit.v`（`branch_unit`） | 计算 `pc + imm` 目标并判断 BEQ、BNE、BLT、BGE、BLTU、BGEU 六类条件分支。 | 分支比较与 ALU 算术解耦，避免为比较语义增加额外 ALU 控制；有符号、无符号条件分别实现。JAL/JALR/MRET 的选择由 EX 主模块处理。 |
| `rtl/core/ex_stage/ex_stage.v`（`ex_stage`） | 对源操作数做前递，选择 ALU 输入并计算结果；处理分支/JAL/JALR/MRET/FENCE.I 重定向和目标对齐异常；识别非法指令、ECALL、EBREAK 等 EX 异常；把结果与控制锁存到 EX/MEM。 | 把操作数修正、执行和分支决策放在同一级，降低关键控制穿越多个 stage 的复杂度。静态顺序取指直到 EX 决定 redirect；redirect 后清除年轻指令。EX 异常信息随指令携带，允许核心按程序顺序提交异常。 |
| `rtl/core/mem_stage/lsu.v`（`lsu`） | 依据地址低位和访问大小生成 SB/SH/SW 的写数据及 4 位 byte mask；对 LB/LH/LW/LBU/LHU 从 32 位读字中选 lane 并符号/零扩展；输出读写使能与地址。 | 以字节 lane 表达非整字访问，适配带 byte-enable 的 RAM/总线接口；访存对齐异常由 MEM 统一检查，LSU 聚焦数据搬运。 |
| `rtl/core/mem_stage/mem_stage.v`（`mem_stage`） | 调用 LSU；计算 CSRRW/CSRRS/CSRRC 的写/置位/清位数据；发现 load/store 非对齐、未实现 CSR 和只读 CSR 写；错误时抑制内存、CSR 和寄存器副作用；选择 ALU/MEM/PC+4/IMM/CSR 写回值并锁存 MEM/WB。 | 把访存阶段的异常与实际副作用门控放在一起，保证出错指令不会部分写内存或寄存器。MEM 指令比 EX 年长，因此异常优先级更高，支持精确异常。 |
| `rtl/core/csr_file.v`（`csr_file`） | 实现机器模式 CSR 读写寄存器和事件更新：MSTATUS、MISA、MIE、MTVEC、MSCRATCH、MEPC、MCAUSE、MTVAL、MIP、MCYCLE/MINSTRET 及高半部、MHARTID，共 14 个地址；处理 trap、MRET 和计数器。 | CSR 状态集中管理，便于统一维护 trap/MRET 规则。`mcycle` 每拍计数，`minstret` 随退休有效指令计数；trap 更新 MEPC/MCAUSE/MTVAL 和 MSTATUS，MRET 恢复 MIE/MPIE。核心对同拍较老 CSR 写入 MTVEC/MEPC 做旁路，保证 trap/MRET 看到正确新值。 |
| `rtl/core/wb_stage/wb_stage.v`（`wb_stage`） | 纯组合生成寄存器堆写端口；只有有效指令、写回使能为真且 `rd != x0` 时才允许写入。 | 最终副作用门控集中在 WB，形成明确的提交边界；即使上游控制异常，也不会写 x0 或无效指令。 |

### 2.1 流水线协作与设计理由

- **同步取指与队列**：IF1 发出 PC，IF2 捕获下一拍的指令。load-use/CSR-use stall 会冻结发射并将 ID/EX 变成 bubble；IF2 的 head/tail skid 项接住 BRAM 已经在途的数据。redirect 或 trap 优先于 stall，清掉错误路径。
- **数据冒险**：普通 ALU、PC+4、IMM 结果由 EX/MEM 前递；更晚的结果由 MEM/WB 前递。load/CSR 结果未就绪时停一拍，再由 MEM/WB 提供。寄存器堆还处理 WB 与 ID 同拍读写。
- **控制冒险**：顺序路径相当于预测不跳转。EX 产生条件分支/JAL/JALR/MRET/FENCE.I redirect；目标 PC 回到 IF1，同时 flush IF2 和 ID 的年轻指令。
- **同步异常与精确性**：EX 产生非法指令、ECALL、EBREAK、指令目标非对齐等异常；MEM 产生 load/store 非对齐和 CSR 异常。MEM 年长，和 EX 同时请求时 MEM 胜出。异常指令及更年轻的指令不产生写回、存储器或 CSR 副作用；trap 进入 `mtvec`，记录 MEPC/MCAUSE/MTVAL。
- **设计边界**：当前 trap 向量按 direct 基址使用；外部中断投递、U/S 特权级、M/A 扩展、Cache/总线握手、FPGA 约束与官方 `riscv-tests` 不在现有实现范围。数据侧换成同步 BRAM 或带等待的总线时，需要额外加入 MEM 等待/保持协议。

### 2.2 指令分类与模块使用关系

本节按活动 `decoder.v` 的实际识别/控制信号分类，不把“同一流水级中有模块实例”误说成“每条指令都会使用该模块的运算”。有效指令共同经过 IF1 → IF2 → ID → EX → MEM → WB；ID 内由 `decoder` 识别并产生控制，`imm_gen` 和 `regfile` 是 ID 的组合数据源。EX 中 `forward_unit`、`alu`、`branch_unit` 均实例化，但各类指令按控制信号只使用其中一部分。MEM 中 `lsu` 与 `csr_file` 也常驻，只有 load/store 或 CSR 指令才产生对应操作。`rv32_core` 负责全局 stall、redirect、flush 和 trap 优先级，`top` 仅连接外部接口。

#### 指令集分组

| 编码/语义类别 | 指令 | 数量 | 主要数据与动作 |
|---|---|---:|---|
| U 型常量/PC 相对 | `LUI`, `AUIPC` | 2 | 生成 20 位高位立即数；LUI 将立即数写入 `rd`，AUIPC 将 PC 与立即数相加后写入 `rd`。 |
| 无条件控制转移 | `JAL`, `JALR` | 2 | 计算跳转目标并冲刷流水线；将 `PC+4` 写入链接寄存器 `rd`。JAL 使用 PC 相对立即数；JALR 使用 `rs1+imm` 并清除目标最低位。 |
| 条件分支 | `BEQ`, `BNE`, `BLT`, `BGE`, `BLTU`, `BGEU` | 6 | 比较 `rs1` 与 `rs2`，条件成立时跳到 `PC+imm`；有符号/无符号比较分别处理。 |
| Load | `LB`, `LH`, `LW`, `LBU`, `LHU` | 5 | 地址为 `rs1+imm`；从字节、半字或字取数，按 signed/unsigned 扩展后写 `rd`。 |
| Store | `SB`, `SH`, `SW` | 3 | 地址为 `rs1+imm`，将 `rs2` 的低字节/半字/字写到存储器对应 byte lane。 |
| 立即数整数运算 | `ADDI`, `SLTI`, `SLTIU`, `XORI`, `ORI`, `ANDI`, `SLLI`, `SRLI`, `SRAI` | 9 | `rs1` 与 I 型立即数做算术、逻辑、比较或移位，结果写 `rd`。移位量使用立即数字段低 5 位。 |
| 寄存器整数运算 | `ADD`, `SUB`, `SLL`, `SLT`, `SLTU`, `XOR`, `SRL`, `SRA`, `OR`, `AND` | 10 | `rs1` 与 `rs2` 做 32 位整数运算，结果写 `rd`。 |
| 存储器排序指令 | `FENCE` | 1 | 当前模型没有 Cache/乱序访存/外部总线缓冲，译码后作为无额外动作的顺序流水指令通过并退休。 |
| 指令流同步 | `FENCE.I` | 1 | 当前实现重定向到自身 `PC+4` 并 flush 取指队列；由于没有指令 Cache，未执行 Cache 清理。 |
| 环境调用/断点 | `ECALL`, `EBREAK` | 2 | 在 EX 级分别产生 machine ECALL 与 breakpoint 同步异常，进入 trap 通路。 |
| CSR 寄存器操作 | `CSRRW`, `CSRRS`, `CSRRC` | 3 | 读旧 CSR 写入 `rd`，并按写/置位/清位规则更新 CSR；源为 `rs1`。 |
| CSR 立即数操作 | `CSRRWI`, `CSRRSI`, `CSRRCI` | 3 | 与上一组相同，但源为指令中的 5 位 `zimm`，零扩展后参与 CSR 操作。 |
| 机器模式返回 | `MRET` | 1 | redirect 到 `mepc`，并让 CSR 文件恢复 `mstatus.MIE/MPIE`。 |

按仓库现有译码清单，工程称为“RV32I 41 条 + Zicsr 6 条”，并额外实现 MRET；这 41 条中包含 `FENCE.I`。严格按 ISA 扩展命名时，`FENCE.I` 通常属于 Zifencei，MRET 属于机器特权指令。因此也可描述为：RV32I 基础部分 40 条 + FENCE.I 1 条 + Zicsr 6 条 + MRET 1 条。两种说法指向同一份工程支持清单，阅读时注意统计口径。

#### 各类指令实际参与的模块

下表先列出会对该类指令数据/控制产生实际作用的模块。所有类别仍会穿过共用的 stage 和流水寄存器；例如即使 ALU 不提供某条指令的最终结果，`ex_stage` 仍接收并推进它。

| 指令类别 | ID：译码与操作数 | EX：执行/控制 | MEM：访存/CSR | WB 与后续 |
|---|---|---|---|---|
| R 型整数运算 | `decoder` 产生 ALU 控制；`regfile` 读取 `rs1/rs2`；`imm_gen` 对 R 型格式返回无效/零立即数，不作为运算输入。 | `forward_unit` 按需修正两个源；`alu` 完成指定运算；`ex_stage` 锁存 ALU 结果。 | `mem_stage` 不访问 LSU，选择 ALU 结果进入 MEM/WB。 | `wb_stage` 门控后写 `rd`；`regfile` 接收写口。 |
| I 型整数运算 | `decoder`、`imm_gen` 产生操作数和运算控制；`regfile` 读取 `rs1`，`rs2` 不被使用。 | `forward_unit` 只需为 `rs1` 选择最新值；`alu` 执行运算。 | `mem_stage` 选择 ALU 结果，不发读写请求。 | `wb_stage` 写回 `rd`。 |
| `LUI` | `decoder` + `imm_gen` 形成 U 型立即数；不依赖 GPR 源操作数。 | `ex_stage` 携带立即数；ALU 虽常驻，但 LUI 的写回选择是 `WB_IMM`，ALU 结果不用于最终结果。 | `mem_stage` 选择 IMM 通路，不访问 LSU/CSR。 | `wb_stage` 把 U 型立即数写入 `rd`。 |
| `AUIPC` | `decoder` + `imm_gen`；不读取 GPR 源。 | `ex_stage` 选择 PC 与立即数，`alu` 做加法。 | `mem_stage` 选择 ALU 结果。 | `wb_stage` 将 PC 相对结果写入 `rd`。 |
| 条件分支 | `decoder` 标记两个源都使用；`regfile` 读 `rs1/rs2`；`imm_gen` 生成 B 型偏移。 | `forward_unit` 解决比较操作数 RAW；`branch_unit` 比较并算 `PC+imm`；`ex_stage` 在 taken 时 redirect，`rv32_core` flush IF2/ID。 | 不读写数据存储器；正常推进退休。 | 不写 GPR，WB 写口由 `wb_en=0` 关闭。 |
| `JAL` | `decoder` + `imm_gen` 生成 J 型偏移；无需 GPR 源。 | `ex_stage` 计算 `PC+imm`，产生 redirect 和 `PC+4` 链接值；不需要 `branch_unit` 的比较功能。 | 不访问 LSU/CSR。 | 若 `rd!=x0`，`wb_stage` 写回 PC+4；redirect 同时 flush 年轻取指。 |
| `JALR` | `decoder`、`imm_gen`；`regfile` 读取 `rs1`。 | `forward_unit` 处理 `rs1` 依赖；`alu` 计算 `rs1+imm` 作为目标，`ex_stage` 清目标最低位、检查对齐并 redirect，同时生成 PC+4。 | 不访问 LSU/CSR。 | `wb_stage` 写回 PC+4 到 `rd`（x0 写入被屏蔽）。 |
| Load | `decoder` + `imm_gen`；`regfile` 读取基址 `rs1`。 | `forward_unit` 处理基址依赖；`alu` 计算有效地址。`hazard_unit` 会在 EX 中 load 的结果被 ID 下一条指令使用时停一拍。 | `mem_stage` 检查半字/字对齐；`lsu` 产生读请求并选取/扩展数据；异常时抑制读请求和写回。 | `mem_stage` 选 MEM 数据；`wb_stage` 将 load 值写入 `rd`。 |
| Store | `decoder` + `imm_gen`；`regfile` 读取基址 `rs1` 和待写数据 `rs2`。 | `forward_unit` 可分别前递基址与 store 数据；`alu` 算地址；数据与控制一起进入 EX/MEM。 | `mem_stage` 检查对齐并屏蔽异常副作用；`lsu` 产生写数据、byte mask 和写使能。 | 不写 GPR；store 正常作为有效指令退休。 |
| `FENCE` | `decoder` 识别为合法 system/misc 指令，不需要 GPR 源。 | `ex_stage` 不产生 redirect；作为无数据运算指令顺序通过。 | 不产生 LSU 操作。 | 不写 GPR，随流水线退休。该实现没有外部排序协议。 |
| `FENCE.I` | `decoder` 识别并设置 `fence_i`，无 GPR 源。 | `ex_stage` redirect 到 PC+4；`rv32_core` flush 取指队列，避免继续使用旧的在途指令。 | 不访问 LSU/CSR。 | 不写 GPR，正常退休。 |
| `ECALL` / `EBREAK` | `decoder` 识别精确 SYSTEM 编码；无 GPR 源。 | `ex_stage` 给出异常 cause/PC/tval；核心合并异常请求并优先接受更老的 MEM trap。 | `csr_file` 在 trap 事件时记录 MEPC/MCAUSE/MTVAL 并更新 MSTATUS；redirect 到 MTVEC。异常指令不提交到有效 MEM/WB。 | 不写 GPR；trap 后冲刷年轻指令，handler 由软件执行。 |
| CSR 六指令 | `decoder` 识别 CSR 地址、操作和是否写 CSR；寄存器形式由 `regfile` 读 `rs1`，立即数形式由 `imm_gen` 生成零扩展 zimm。`CSRRS/CSRRC` 的 `rs1=x0`、立即数变体的 `zimm=0` 标记为纯读。 | `forward_unit` 可为寄存器源前递；`ex_stage` 将 CSR 操作类型、源数据和地址传入 EX/MEM。CSR 读值不在 EX 前递，`hazard_unit` 对紧邻 CSR 结果消费者停一拍。 | `csr_file` 按地址读出旧值；`mem_stage` 计算 write/set/clear，检查地址是否实现及是否只读，再形成 CSR 写口；非法 CSR 访问触发非法指令异常。 | 旧 CSR 值由 `WB_CSR` 路径经 `mem_stage`/`wb_stage` 写入 `rd`；CSR 新值写入 `csr_file`。`rd=x0` 只抑制 GPR 写回，不会自动取消 CSRRW 对 CSR 的写。 |
| `MRET` | `decoder` 识别 MRET，不需要 GPR 源。 | `ex_stage` 从核心提供的 `mepc` 形成 redirect 目标、做对齐检查并 flush 年轻指令。 | `csr_file` 根据 MRET 事件恢复 MSTATUS 的 MIE/MPIE/MPP；MRET 不经普通 CSR 写数据路径。 | 不写 GPR；作为有效指令推进并退休。 |
| 非法/不支持编码 | `decoder` 置 `illegal`，GPR 源使用提示清零，副作用控制无效；仍保留 PC/指令用于异常报告。 | `ex_stage` 生成 illegal-instruction trap，并禁止该指令的正常 EX/MEM 副作用。 | trap 写 CSR；非法指令不发内存写或 CSR 普通写。 | 不产生正常 GPR 写回；核心 redirect 到 MTVEC。M 扩展指令属于此类。 |

#### 从汇编到模块的快速索引

```text
ADD/SUB/逻辑/移位     → decoder + regfile + forward_unit + alu + WB
ADDI/比较/移位立即数  → decoder + imm_gen + regfile(rs1) + forward_unit + alu + WB
LUI / AUIPC           → decoder + imm_gen / (AUIPC 另用 alu) + WB
BEQ/BNE/BLT/BGE/...   → decoder + regfile + imm_gen + forward_unit + branch_unit + redirect/flush
JAL / JALR            → decoder + imm_gen + (JALR 另用 rs1/alu) + redirect/flush + PC+4 写回
LB/LH/LW/LBU/LHU      → decoder + imm_gen + regfile + alu(地址) + mem_stage + lsu + WB
SB/SH/SW              → decoder + imm_gen + regfile + alu(地址) + mem_stage + lsu
CSRRW/CSRRS/CSRRC/... → decoder + regfile 或 zimm + mem_stage + csr_file + WB
ECALL/EBREAK          → decoder + ex_stage 异常 + rv32_core 优先级/redirect + csr_file trap 更新
MRET                  → decoder + ex_stage redirect + csr_file 状态恢复 + flush
FENCE/FENCE.I         → decoder + 顺序流水 / (FENCE.I 额外 redirect+flush)
```

这里的“模块使用”指语义上确实读取、计算或修改其数据/控制。模块层级可能仍然常驻（比如普通 ALU 指令经过 MEM stage），但其读写使能关闭或结果被忽略。完整硬件连接以 `rtl/core/rv32_core.v` 的实例连接为准，各指令的控制编码以 `rtl/core/id_stage/decoder.v` 为准。

## 3. 整核测试与测试程序

`model_tb/` 同时包含一个原有整核定向程序和 17 个模块级 bench。模块 bench 直接实例化活动 RTL；整核程序由 Python 汇编 DSL 生成机器码和期望值。这样把局部组合/时序问题与跨级流水线问题分层定位。

| 文件 | 功能 | 设计考虑 |
|---|---|---|
| `model_tb/tb_top.v`（`tb_top`） | 整核测试顶层：搭建时钟/复位、指令与数据存储器模型，加载 `program.hex`，按结果序号与 `expected.hex` 比较，并按顺序核对 trap cause、MEPC、MTVAL 等。 | 用真实指令流穿过全核而非直接驱动内部控制信号，覆盖译码、冒险、写回及异常协同；结果通过内存约定输出，便于批量 scoreboard 检查。 |
| `model_tb/filelist.f` | 活动 RTL 的仿真编译清单，列出当前 `top`、核心及其模块依赖。 | 明确隔离活动版本与同名历史模块；回归脚本用它检查活动模块是否均有单测。 |
| `model_tb/unit/core_test_env.vh` | `tb_rv32_core` 和 `tb_top_module` 共享的测试辅助代码：小型同步指令/数据存储器、常用指令编码函数、trap 检查、写入检查、程序初始化和完成签名。 | 共用测试程序和 scoreboard 可减少重复；两个 bench 仍各自直接实例化被测核心或顶层，能分别检查边界接口。 |
| `model_tb/unit/tb_rv32_core.sv` | 直接测试 `rv32_core` 的两段小程序：前递、load/CSR-use、错误路径抑制、ECALL/trap handler/MRET，以及 MEM 与 EX 异常同拍时的优先级。 | 在大回归之外单独验证核心集成和精确异常；共享 env 保持场景一致。 |
| `model_tb/unit/tb_top_module.sv` | 直接测试薄顶层 `top`，复用相同两段程序及核心端到端断言。 | 额外验证顶层外部端口没有漏接或接错，避免只测 `rv32_core` 而漏掉集成壳。 |

各独立单元 bench 的职责如下（检查范围来自对应 bench/单测清单）：

| Testbench | 被测对象与重点 |
|---|---|
| `tb_alu.sv` | 10 类 ALU 运算，含符号比较和算术移位。 |
| `tb_branch_unit.sv` | 六类分支比较、branch disable 和目标地址。 |
| `tb_forward_unit.sv` | EX/MEM 优先级、x0 排除、load/CSR 不允许 EX/MEM 前递。 |
| `tb_imm_gen.sv` | I/S/B/U/J/CSR 格式立即数与符号扩展。 |
| `tb_regfile.sv` | x0 恒零、寄存器读写、同拍写优先旁路。 |
| `tb_hazard_unit.sv` | load-use/CSR-use、无效或非法指令、x0 和未使用源的过滤。 |
| `tb_if1_stage.sv` | PC+4、stall 保持、redirect 优先级、取指 valid 延迟。 |
| `tb_if2_stage.sv` | 16 类取指队列边界场景，包括 PC=0、head/tail 去重、skid 晋升、flush 优先。 |
| `tb_decoder.sv` | 算术、访存、CSR、ECALL 等译码，以及非法指令副作用控制。 |
| `tb_id_stage.sv` | ID/EX 寄存、寄存器读写联动和 flush。 |
| `tb_lsu.sv` | byte lane、半字/整字掩码、符号扩展和零扩展。 |
| `tb_csr_file.sv` | CSR 地址读写、高低计数器/进位、retire 门控、trap/MRET 及同拍事件先后。 |
| `tb_wb_stage.sv` | valid、写使能和 x0 对 WB 写端口的门控。 |
| `tb_ex_stage.sv` | 21 项执行级检查，覆盖 IMM/PC+4/MEM-WB 前递、跳转目标对齐、系统异常、MRET/FENCE.I 和 MEM 异常优先。 |
| `tb_mem_stage.sv` | 20 项 MEM 检查：5 路写回选择、CSR 写/置位/清位、只读/未实现保护、非对齐副作用抑制。 |

单元 bench 的时钟、刺激、检查和 PASS 标记均在各自 SV 文件中；断言失败以 `$fatal` 结束，回归器不会把普通日志里的“PASS”误当成通过。

### 3.1 指令程序生成与派生文件

| 文件 | 角色 |
|---|---|
| `model_tb/program/gen_test.py` | 可编辑的测试源。`Asm` 类提供 R/I/U/load/store/branch/jump/CSR/system 等编码器、标签修补、检查结果与 trap 期望收集，最后输出镜像。扩展整核测试应编辑它而不是手改 HEX。 |
| `model_tb/program/program.hex` | 生成的指令存储器镜像，一行一个 32 位机器指令。 |
| `model_tb/program/expected.hex` | 生成的结果内存期望值，按 scoreboard 顺序排列。 |
| `model_tb/program/trap_expected.hex` | 生成的同步异常 cause 顺序期望。 |
| `model_tb/program/defs.vh` | 生成的结果数、trap 数等宏，供 testbench 与镜像数量对齐。 |
| `model_tb/program/checks.txt` | 结果索引与测试名映射，便于从失败编号反查测试意图。 |
| `model_tb/program/README.md` | 镜像布局、寄存器约定、覆盖范围及扩展方法说明。 |

当前基线为 380 个指令字、89 个结果和 8 个 trap。`imem` 与 `dmem` 为独立数组：入口位于 0，trap handler 位于 `0x80`，测试主体从 `0x100` 开始；结果、数据和 trap 日志各有约定区域。HEX 与文本索引是生成数据，不是处理器 RTL。

| 文件 | 功能与设计理由 |

| 工作区根 `../Makefile` | 把常用 make 目标转发到 `RISC-V32/model_tb`，让用户从工作区根目录执行仿真、单测、完整回归、程序生成和清理。 |

## 5. 归档 RTL：用于对照，不是当前实现

`rtl/legacy/` 保存处理器演进过程中的代码。它们和当前模块存在大量同名定义，不能与活动 RTL 同时编译。历史版本的价值是对比结构和理解功能逐步增加的过程；当前 filelist 不引用这些目录。

### 5.1 旧单周期实现（`rtl/legacy/single_cycle/`）

| 文件 / 模块 | 历史职责 |
|---|---|
| `top.v`（`top`） | 将取指、译码、寄存器堆、ALU、分支、LSU、写回等组合数据通路连成单周期处理器；PC 在时钟沿更新。 |
| `pc_reg.v`（`pc_reg`） | 带低有效复位的 PC 时序寄存器，采样下一 PC。 |
| `pc_plus4.v`（`pc_plus4`） | 组合计算顺序执行地址 PC+4。 |
| `mux.v`（`mux`） | 根据 PC 来源选择顺序地址、JALR、JAL 或条件分支目标。 |
| `mux_2_alu.v`（`mux_2_alu`） | 从寄存器、PC 或零等候选中选 ALU 操作数。 |
| `deocde.v`（模块名 `decode`） | 根据 opcode/funct 识别内部指令编号和格式，提供源操作数使用提示及非法指令识别；文件名 `deocde` 是仓库原名。 |
| `control_unit.v`（`control_unit`） | 依据内部指令编号生成寄存器写回、ALU、访存、分支、立即数格式和 PC 控制。 |
| `instr_decoder.v`（`instr_decoder`） | 早期独立替代译码器，根据 opcode/funct 直接输出立即数格式、ALU/访存/分支/CSR/system 控制和非法标志；与 `deocde.v` 代表重复保留的译码实现，均不在当前 filelist 中。 |
| `README.md` | 该单周期目录的历史说明与入口介绍。 |

单周期结构让一次指令执行的完整组合路径直观，适合早期验证指令语义；代价是时钟周期必须覆盖最长路径，且没有流水线吞吐率。后来的流水线版本把寄存器边界插入数据通路，因此这套实现被保留作教学/对照材料。

| `core/if_stage/if1_stage.v`（`if1_stage`） | 旧版 PC/顺序取指/重定向级。 |
| `core/if_stage/if2_stage.v`（`if2_stage`） | 旧版同步指令返回捕获及 IF2 队列逻辑。 |
| `core/id_stage/decoder.v`（`decoder`） | v2 指令识别及控制译码。 |

| `core/id_stage/id_stage.v`（`id_stage`） | v2 译码、寄存器读取与 ID/EX 流水寄存。 |

## 7. 修改代码时的推荐路径

1. 新增或修正指令行为时，先核对 `riscv_def.vh`、`decoder.v`、`imm_gen.v`、对应执行/访存逻辑及写回控制的职责边界。
2. 组合小模块先跑对应 `make unit-<module>`；跨级控制或旁路变更还要跑 `tb_rv32_core` 和 `tb_top_module`。
3. 修改整核定向用例时编辑 `model_tb/program/gen_test.py`，运行 `make program` 更新 HEX/期望产物，再跑 `make sim`。
4. 完成后运行 `make regression-check`，它包含 17 个模块单测和整核指令程序；如改动回归脚本，再运行 `make test-runner`。
5. 只把 `rtl/core/` 当作活动处理器实现。除非明确在维护历史材料，不要编辑或编译 `rtl/legacy/` 来修正当前行为。
